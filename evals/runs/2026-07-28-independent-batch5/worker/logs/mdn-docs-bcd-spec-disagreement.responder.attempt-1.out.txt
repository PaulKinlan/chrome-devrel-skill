## 3. Challenge (selected lenses)

**Interoperability & compatibility (primary).**
- *Fact:* Spec = `Promise`. *Fact:* Chrome 149 = `void`. *Contradiction:* these cannot both be the documented contract.
- *Recommendation:* Treat this as an interop defect, not a doc task. The resolution path is: (a) confirm intent with the API Owner/spec editor; (b) either fix Chrome to return `Promise`, or amend the spec to `void` with editor + cross-engine agreement; (c) add/align a WPT test to the agreed contract; (d) *then* update MDN to match the agreed, tested contract.
- *Unknown:* Mozilla/WebKit positions on the return type. Do not assume.

**Documentation, samples, and support.**
- *Recommendation:* MDN documents the **standard contract**, with implementation deviations noted as such — it does not retroactively rewrite the contract to match one engine. If the team is *certain* void is intended, the spec must move first (a normative PR), and MDN then reflects the amended spec with a clear "Changed in spec version X / shipped in Chrome 149" note.

**Adoption mechanics / Baseline.**
- *Hypothesis:* If we publish "supported everywhere," Baseline/tooling (`@mdn/browser-compat-data`, RUM-based Baseline) will be poisoned. Baseline requires multi-engine convergence; a single conformant-or-not engine is not "newly available."

**Launch resilience & integrity.**
- *Recommendation:* Decline the literal ask in writing (this response serves that function), with a one-paragraph rationale the requester can forward. This protects the doc maintainers and the developers, and gives the team a clean record of *why* the edit is deferred.

**What I will *not* do.**
- I will not mark any browser "supported" without a BCD PR + version evidence.
- I will not silently document `void` as the contract while the spec says `Promise`.
- I will not invent Mozilla/WebKit/other-engine support.

**Concrete ways to close each gap:**
- Spec/impl: file a spec issue + an intent-to-(fix|amend) thread; get API Owner call.
- Cross-browser support: open BCD PR for Chrome 149 only; ping Mozilla/WebKit standards contacts for their positions/versions (don't infer).
- Conformance: add/align a WPT test asserting the agreed return type; add an entry to the regression/conformance plan.
- MDN: produce the provisional, correctly-scoped draft below (artifact).
