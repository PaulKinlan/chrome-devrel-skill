## Why archived outside the installable tree

The tracked corpus contains cached source records and thousands of historical outbound URLs. One automated marketplace scanner assigned a critical rating because threat intelligence classified an official standards-group GitHub Pages hostname as malicious, while the scanner's own prose analysis called the alert a false positive. W3C's Immersive Web Working Group [tools page](https://www.w3.org/groups/wg/immersive-web/tools/) independently links that group's GitHub repositories and specification/sample sites.

The URL was passive data copied from a ChromeStatus snapshot, not an instruction, download, executable dependency, redirect, or runtime network target. Even so, raw research corpora do not belong in an installed agent skill. Archiving the tracked evidence/report corpus preserves reproducible denominators and provenance while reducing installation size, scanner noise, prompt-injection surface, and accidental traversal of stale third-party links.

## Archive scope

The pinned Git tree contains every file that was tracked on the default branch: manifests, source evidence, metrics evidence, reports, revisions, and run metadata. Both retrospective validators pass against an extraction of this tree.

The run's ignored `worker/` directory was **not** part of commit `7f629c2` or the public tag. A surviving local scratch copy contained 580 files / 4,852,702 bytes of provider logs, transient statuses, and raw model outputs. Those files were never part of the validated public denominator, were excluded by the repository's prior `.gitignore`, and may contain untrusted provider output. They are intentionally not represented as archived public evidence. This record therefore makes no 1,708-file or 41.5-MB completeness claim.
